# ImGui Editor Starter Kit

Каркас редактора на C++17: Dear ImGui + OpenGL, с подсистемами документа,
undo/redo, плагинов, задач и эффектов. **Собирается офлайн одной командой.**

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Сети не требуется. Все зависимости лежат в `third_party/`.

## Что внутри

4 782 строки в 24 файлах, разложенные по подсистемам, а не размазанные по
`main.cpp`:

| Подсистема | Назначение |
|---|---|
| `core` | Application, Window, Logger, Types |
| `document` | Document, Layer, Composition, PixelBuffer |
| `undo` | UndoStack, Command |
| `plugin` | PluginManager |
| `task` | TaskScheduler |
| `effect` | Effect, EffectPipeline |
| `render` | Renderer, Shader, Texture, Framebuffer, VertexArray, Mesh |
| `ui` | EditorUI, Panel, DockingSpace, Style, ImGuiLayer |

## Три решения, из-за которых это интересно читать

**Зависимости вендорёны, а не тянутся.** GLFW, Dear ImGui и stb лежат в
`third_party` — 61 МБ исодников в репозитории. CMake их не качает.

Раньше стоял `FetchContent` на все три, и это было противоречие: копия
зависимости лежала в дереве, а сборка её игнорировала. Последствие не
очевидное — проект не собирался без сети, хотя всё нужное было рядом.
Теперь `FetchContent` в проекте нет вообще.

**GL-загрузчик вендорён целиком и компилируется в одном файле.**
Функций GL 3.x (шейдеры, VAO, FBO) нет в `opengl32.lib` — там только
GL 1.1, поэтому линкер их не находит и адреса берутся в рантайме.

- `third_party/glad/gl.h` — GLAD 2, 326 КБ, MIT, header-only
- `src/render/glad_impl.c` — **единственный** TU, где он компилируется

Второй пункт неочевиден и стоил больше всего времени. GLAD 2 разделяет
заголовок на объявления и определения: указатели `glad_gl*` объявлены
везде, но определены только там, где перед включением задан
`GLAD_GL_IMPLEMENTATION`. Без этого файла линкер выдаёт
`undefined reference to glad_glViewport` и десятки таких же. Именно
поэтому в `project()` объявлен `LANGUAGES C CXX` — реализация GLAD
написана на C.

**Список исходников явный, и его count проверяется.** Не `GLOB`: новый
файл в каталоге при `GLOB` молча попадает в сборку, и через месяц никто
не помнит, откуда он взялся. `set(EDITOR_SRC_EXPECTED 24` — если добавили
модуль и забыли прописать, конфигурация скажет об этом сразу.

## Загрузчик: почему не GLEW

Первая версия тянула GLEW через `FetchContent` по тегу `glew-2.2.0`.
В этом теге лежит **только шаблон** `src/glew.c.in`; настоящий `glew.c`
генерируется отдельным шагом сборки, который CMake не выполняет.
Конфигурация падала: `Cannot find source file ... glew-src/src/glew.c`.

GLEW вне поддержки, а GLAD 2 решает ту же задачу одним файлом.

## CI

Workflow собирает проект на каждом коммите и **падает**, если кто-то
вернёт GLEW, вернёт `FetchContent` для glad или удалит
`third_party/glad/gl.h`. Обе поломки молчаливые до чистой машины, и
именно на них проект и стоял.

## Границы

- Windows и MinGW-w64. Проверено на Windows 11, CMake 3.30, g++ 14.2.
- Приложение создаёт окно и контекст OpenGL. Без видеокарты в CI
  бинарник собирается, но не запускается — поэтому smoke-теста
  рендера здесь нет.
- Это каркас, а не готовый редактор: узлы графа, композитор и плагины
  заданы интерфейсами, реализация под каждым — под вами.
